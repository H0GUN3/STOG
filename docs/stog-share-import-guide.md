# STOG 공유 담기와 여행 가이드 AI 참고 자료

> 이 문서는 자료 조사와 제품 피드백을 바탕으로 만든 **참고 가이드**다.
> `docs/*.yaml`의 확정된 사실이나 기능 범위를 대신하지 않는다.
> 충돌이 있으면 `glossary.yaml`, `product.yaml`, `architecture.yaml`이
> 우선하며, 새로운 기능을 확정하려면 해당 YAML의 `open_items`와
> `decisions` 절차를 따른다.

## 핵심 방향

STOG는 외부 앱의 여행 정보를 가져와서 사용자가 만든 계획을 정리하고,
필요할 때 여행 가이드 AI가 다음 선택을 돕는 서비스로 발전할 수 있다.

```text
외부 앱 공유
  → share_import 보존
  → place 후보 추출
  → 사용자 확인
  → 계획(plan)에 담기
  → 지도와 trail 배치
  → 여행 중 필요할 때 AI 가이드 호출
```

AI가 처음부터 임의의 계획을 만드는 것이 핵심이 아니다. 사용자가 모은
장소와 조건을 보존하면서, 더 효율적인 배치와 다음 행동을 제안하는 것이
핵심이다.

## 1. 공유 담기(share_import)

### 기본 흐름

1. 다른 Android 앱에서 STOG로 공유한다.
2. 원본 텍스트·링크·파일을 제한된 기간 동안 보존한다.
3. 원본에서 `place` 후보를 찾는다.
4. 지도 서비스에서 후보를 검색한다.
5. 사용자가 후보를 선택하거나 직접 검색한다.
6. 확인된 장소만 계획과 trail에 반영한다.

장소를 찾지 못하거나 여러 후보가 나오는 것은 정상적인 결과다.
`미확인`, `여러 후보`, `직접 선택` 상태를 지원한다.

### Android 입력 원칙

- `ACTION_SEND`와 `ACTION_SEND_MULTIPLE`을 처리한다.
- 텍스트, 링크, 이미지, `EXTRA_STREAM`, `ClipData`를 구분한다.
- action, MIME type, extra, URI의 파일명과 길이는 입력 앱의 주장으로
  취급한다.
- 실제 bytes를 읽기 전에 파일 개수와 크기를 제한한다.
- 계속 사용할 파일은 앱이 관리하는 저장소로 복사한다.
- 공유 수신부와 장소 추출·검색·계획 생성 기능을 분리한다.
- shortcut ID와 calling-app 정보는 인증이나 장소 진위의 근거로 쓰지
  않는다.

Android 기본 Sharesheet 사용은 플랫폼과 맞는 선택이지만, 기본 Sharesheet가
직접 만든 선택창보다 더 빠르거나 안전하다는 직접 비교 연구는 확인되지
않았다.

## 2. 장소 후보와 확인

AI, NER, OCR, 이미지 분석이 찾은 장소명은 정답이 아니라 후보다.

예를 들어 `객사 근처 카페`, `전주 웨리단길`, `바다 보이는 숙소`는
여러 장소를 가리킬 수 있다. 다음 정보를 함께 보존한다.

- 원문에서 장소가 발견된 문장과 위치
- 장소 유형: 주소, 가게, 거리, 지역, 명소 등
- 정규화한 검색어
- provider별 후보와 주소·지역·분류·좌표
- 미확인 또는 애매한 이유
- 모델·검색 시각·provider 버전

상위 후보 몇 개를 보여주더라도 목록 밖에 정답이 없다고 단정하지 않는다.
사진 분석이나 게시물 위치 정보는 후보 순위를 바꾸는 참고 자료일 뿐,
자동 확정의 근거가 아니다.

`user_confirmed` 하나만 저장하지 않는다. 최소 상태는 다음과 같다.

```text
미검토 → 선택됨 / 거절됨 / 수정됨 → 다시 확인 필요
```

선택 결과에는 선택된 장소·좌표, 원문, 후보 목록, 모델/provider 버전,
선택 시각, 다시 확인할 이유를 함께 기록한다.

## 3. 사용자가 만든 장소 목록의 계획 최적화

사용자가 장소를 직접 담아 목록을 만든 뒤, AI 또는 알고리즘이 다음을
계산해 현재 배치가 비효율적인지 판단한다.

- 이동시간
- 방문시간
- 영업시간과 휴무·휴식시간
- 걷는 거리
- 지역과 이동 순서
- 사용자가 고정한 장소
- 예산과 일행의 성향

비효율이 발견되면 사용자 목록을 몰래 삭제·변경하지 않고 제안한다.

```text
현재 배치
  → 효율 분석
  → 더 나은 순서 또는 대안 제안
  → 사용자 승인
  → 계획과 trail에 반영
```

사용자가 반드시 가고 싶은 장소는 `고정`할 수 있어야 한다. 일정이
이미 충분히 효율적이면 불필요하게 새 계획을 만들지 않는다.

일정에 trade-off가 있을 때만 다음과 같은 2~3개 안을 제공한다.

- 기본안: 사용자가 담은 장소를 최대한 유지
- 이동 최적화안: 이동시간과 걷는 거리를 줄임
- 여유 일정안: 일부 장소를 빼고 여유를 확보

각 안에는 이동시간, 걷는 거리, 예상 비용, 빠지는 장소, 장점과 단점을
표시한다. AI가 하나의 정답을 강제하지 않고 사용자가 비교해 선택한다.

## 4. 그룹 여행 가이드

그룹의 모든 대화를 매번 AI에 보내거나 자동 분석하지 않는다. 기본
대화는 일반 채팅으로 유지하고 사용자가 `AI에게 질문하기` 버튼이나
질문 preset을 눌렀을 때만 AI를 활성화한다.

질문 시에는 필요한 범위의 계획, 장소 목록, 현재 위치·시간과 사용자가
허용한 관련 대화만 전달한다. AI는 구성원의 성향과 사용자가 담은
장소를 참고하되, 대화에 없는 의사를 추측하지 않는다.

그룹 의견을 지원할 때 참고할 수 있는 자료는 다음과 같다.

- 여러 사용자가 담은 장소
- 좋아요·투표
- 계획에 고정한 장소
- AI에게 직접 한 질문
- 사용자가 허용한 관련 대화

모든 의견을 자동으로 확정하기보다 `선호`, `보류`, `충돌`, `확인 필요`로
표시하고 사용자가 결정하도록 한다.

## 5. 여행 중 AI 가이드

하단 채팅창에서 사용자가 필요할 때 AI 가이드를 호출한다.

예시:

> “여기가 휴식시간이라 못 갔어. 주변 음식점 괜찮은 곳 있어?”

답변에 활용할 수 있는 정보는 다음과 같다.

- 현재 위치와 시각
- 방문 완료한 장소
- 남은 계획과 trail
- 영업 상태와 휴식시간
- 일행의 성향
- 현재 위치 주변의 후보
- 제휴 reward 정보

답변은 채팅으로 끝내지 않고 다음 행동과 연결한다.

- 후보를 지도에 표시
- 장소를 목록에 추가
- 기존 장소와 교체
- 다음 방문지로 지정
- 쿠폰 확인

추천 장소의 사실과 추정은 구분해 표시한다. 영업 여부·가격·쿠폰처럼
시간에 따라 바뀌는 정보는 최신 확인 시각을 함께 보여준다.

## 6. 여행 중 재계획

다음 상황에서 AI 가이드가 재계획을 제안할 수 있다.

- 일정이 늦어짐
- 장소가 닫혔거나 휴식시간임
- 이동거리가 예상보다 김
- 예상보다 빨리 도착함
- 주변에 이용 가능한 제휴 장소가 있음

일정을 자동 확정하지 않고 제안 카드로 보여준다.

> 현재 일정이 늦어졌습니다. 주변 장소를 추가하면 이동시간을 줄일 수
> 있습니다. 계획에 추가할까요?

사용자는 다음 중 하나를 선택한다.

- 추가
- 기존 장소와 교체
- 무시
- 나중에 보기

큰 우회, 예약·비용, 운영시간, 안전·접근성에 영향을 주는 변경일수록
더 분명한 확인을 요구한다. 되돌릴 수 있는 변경에는 미리보기와 실행
취소를 제공한다.

관광객을 대상으로 추천 장소 수락 뒤 계획을 다시 계산한 소규모 현장
연구는 있지만, 수락률·거절률·오류율·대조군·재계산 품질까지 검증한
것은 아니다. 따라서 이 기능의 효과는 구현 전에 별도 검증해야 한다.

## 7. provider와 실제 장소

네이버·카카오·TMAP의 장소 ID는 서로 다른 체계다. provider 장소,
STOG가 관리하는 실제 장소, 사업자 이력을 분리한다.

이름만으로 장소를 합치지 말고 주소·지역·분류·좌표 등 여러 정보를
비교한다. 잘못 합친 경우 다시 나눌 수 있도록 merge/split을 되돌릴 수
있게 한다.

같은 장소인지 애매하거나 이동거리·예약·접근성에 영향이 큰 경우에만
사용자 검토를 요구한다. 모든 장소를 매번 수동 검토한다는 뜻은 아니다.

## 8. 개인정보와 보관

- 원본, 미리보기, 추출 결과, 검색 후보, cache, 색인, 임베딩을 구분한다.
- Android Auto Backup 포함 여부를 확인한다.
- provider로 보내는 필드를 최소화한다.
- 보관기간, 학습 사용 여부, 하위 처리자, 보관 지역, 삭제 절차를
  확인하기 전에는 provider 장기 보관을 전제로 하지 않는다.
- 사용자가 삭제하면 원본뿐 아니라 파생 데이터·cache·대기 작업·내보내기
  결과도 삭제 대상으로 삼는다.
- 삭제 영수증에는 원본 내용을 넣지 않는다.

암호화·백업 제외·TTL을 적용해도 외부 provider의 모든 복사본이 즉시
사라진다고 보장할 수 없다.

## 9. 현재 문서와의 관계

이 가이드의 AI 여행 가이드, 그룹 의견 정리, 실시간 재계획, OCR,
provider 연동은 조사와 제품 피드백을 정리한 참고 방향이다. 현재
제품의 확정 범위가 아니다.

구현을 시작할 때는 먼저 다음을 확인한다.

1. `docs/glossary.yaml`의 용어와 금지 표현
2. `docs/product.yaml`의 기능 ID·우선순위·`out_of_scope`
3. `docs/architecture.yaml`의 확정 스택·API·알고리즘
4. `docs/conventions.yaml`의 변경·PR 규칙
5. `docs/pitfalls.yaml`의 역할별 주의사항

이 가이드와 YAML이 충돌하면 YAML을 고치지 않고 먼저 `open_items`에
질문을 남긴다.
