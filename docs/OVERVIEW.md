# STOG

> **이 문서는 사람이 읽는 문서입니다.**
> 사실의 원본은 `product.yaml`과 `glossary.yaml`이며, 내용이 충돌하면 **yaml이 우선합니다.**
> 여기서 새로운 결정을 하지 마세요. 결정은 `product.yaml`의 `decisions`에만 추가합니다.

---

## 한 줄로

**걸어온 길과 그곳에서 본 것을 셀에 담아 두는 여행 기록·계획 서비스.**

STEP + LOG. 지도 위 육각형 셀 하나하나가 "내가 거기 있었다"는 기록이 되고, 그 안에 사진과 후기가 담깁니다.

---

## 왜 만드는가

### 진짜 문제

전주에 처음 온 사람이 "웨리단길"을 검색하면 아무것도 안 나옵니다. 객사도 마찬가지입니다.

이건 앱이 게을러서가 아닙니다. **사람들이 실제로 쓰는 지역명은 행정구역과도, 공식 관광지 경계와도 일치하지 않아서 어떤 공개 데이터셋에도 존재하지 않습니다.** 그래서 검색 기반으로 만든 서비스는 원리적으로 이 공백을 못 메웁니다.

결과적으로 이런 일이 벌어집니다.

- SNS나 드라마에서 본 장소를 찾으려면 그 동네를 직접 걸어야 함
- 목적지 정하고 나면 주변 카페·음식점을 다른 앱에서 또 검색
- 일정 순서 하나 바꾸는 게 번거로워서 계획 수정을 포기
- 여행이 끝나면 사진은 사진첩에, 기억은 머릿속에 따로 흩어짐

### 실제로 그런지 확인했나

트리플과 젠트립 리뷰를 봤습니다.

- "검색되지 않는 장소가 많다" — **두 앱 모두** 반복 지적
- "일정 순서 변경이 불편하다" — **두 앱 모두 최다 불만 영역**
- 두 앱 모두 계획 기능은 칭찬받고, 예약·사후 대응에서 신뢰를 잃습니다

문제는 실재하고, 기존 서비스의 구조에서 나옵니다.

## 우리는 뭐가 다른가

### 1. 없는 거리를 만들어냅니다

웨리단길 데이터가 없으면 **우리가 생성합니다.**

1. 공공데이터(상가업소 정보)로 카페·음식점·주점이 몰린 셀 군집을 자동 추출 → "이름 없는 거리 후보"
2. 사용자가 이름을 제보하고 투표 → "웨리단길" 확정
3. 사진·방문·좋아요로 경계를 계속 갱신

> **공공데이터가 커버하지 못하는 공백을 사용자 행동 데이터로 메우고,
> 그 결과물을 다시 공공적 가치를 가진 지역 상권 데이터로 되돌려준다.**

이 문장이 계획서에서 가장 중요한 한 줄입니다. 단순 공공데이터 시각화와 갈라지는 지점이 여기입니다.

### 2. DB에 없어도 담깁니다

인스타에서 본 카페를 공유 담기로 STOG에 넘기면 바구니에 들어옵니다. 기존 앱은 자체 DB에 없으면 끝이지만, 우리는 외부에서 받아옵니다.

**데모 첫 30초에 이걸 보여줘야 합니다.**

### 3. 셀을 채우는 게 아니라 셀에 담습니다

Hexplorer라는 앱이 이미 있습니다. H3 육각 격자로 이동을 추적하고, 다닌 만큼 셀에 불이 들어옵니다. 겹쳐 보이지만 결정적 차이가 있습니다 — **그 앱은 데이터를 수집하지 않는다고 명시합니다.** 서버가 없다는 뜻이고, 공유도 추천도 커뮤니티도 불가능합니다.

지도를 다 채우는 커버리지 게임이 아닙니다. 육각형은 그릇이고, 우리 차별점은 **그 안에 무엇이 담기는가**입니다.

심사에서 "이미 있는 앱 아니냐"가 나오면 이렇게 답하면 됩니다.

> Hexplorer는 셀을 채우는 앱이고, STOG는 셀에 담는 앱입니다.

## 무엇을 만드는가

### 여행 전 — 계획

인스타·네이버지도·카카오지도에서 공유 담기로 담고, 검색으로 더 담습니다. 카드 대시보드에서 순서를 바꾸고 중간에 끼워 넣습니다. AI가 "이 일정은 이동시간 초과"라고 잡아주고, 도보와 대중교통 동선을 짭니다.

**카드 대시보드가 우리의 승부처입니다.** 경쟁 앱 두 곳의 최다 불만 영역이고, 데모에서 가장 공들여야 할 화면입니다.

### 여행 중 — 기록

여행 모드가 켜지면 걸어가는 대로 셀이 채워집니다. 목표 장소에 30분 있으면 방문으로 잡히고, 벗어나면 "경기전은 어떠셨나요?"가 뜹니다. 중앙 버튼으로 사진을 찍으면 그 셀에 저장됩니다.

지나가다 꿀 셀을 만나면 쿠폰이 나오고, 매장 QR로 사용합니다.

### 여행 후 — 남기고 나누기 ⭐

**여기가 1순위입니다.**

보관함에 여행이 쌓입니다. 지도에 내가 걸은 셀이 그대로 남고, 사진은 게시물 형태로 정리됩니다. 공개로 바꾸면 다른 사람이 좋아요를 누르고 일정을 복사해 갑니다.

단순 여행 계획 앱이 아닙니다. **흘러가는 시간 속에서 내가 어디 있었고 무엇을 봤는지를 공간과 함께 남기는 것**이 이 프로젝트의 본질입니다.

## 어디까지 만드나

4주, 5명. 전부 만들되 **완성도 목표를 4단계로 나눕니다.**

| 등급 | 뜻 | 대표 기능 |
|---|---|---|
| **P0** | 심사위원이 직접 누르는 경로. 결함 없이 | 셀 렌더링, 여행 모드, 사진 저장, 일정 바구니, **카드 대시보드**, 보관함 |
| **P1** | 없으면 STOG가 아님 | 공유 담기, AI 일정 검증·동선, 공공데이터 배지 셀, 방문·통과 판정, 공개 피드, 캘린더, 사진 좋아요 |
| **P2** | 화면과 로직은 완성, 데이터는 제한적 | 쿠폰, 그룹 여행, 성향 설문, 행사 페이지, 무장애 정보 |
| **P3** | 사전 계산된 결과로 흐름 시연 | 거리 군집 추출, 명명·투표, 제휴처 정산 |

P3는 "안 만든다"가 아니라 **실시간 연산 대신 미리 계산해둔 걸 보여준다**는 뜻입니다. 거리 군집은 전주 한두 곳만 미리 뽑아두면 데모에서는 똑같이 보입니다.

### 안 만드는 것

웹 버전, 자차 길찾기, 혼잡도 예측, 실시간 공동 편집, 외부 평점 연동, 마이크로서비스, 학습 기반 추천 모델, 이미지 OCR.

**전부 한 번 검토하고 뺀 것들입니다.** 되살리고 싶으면 `product.yaml`의 `decisions`에서 왜 뺐는지 먼저 읽어주세요.

## 팀이 지켜야 할 것

### 용어를 지어내지 마세요

`glossary.yaml`에 40개 용어가 정의돼 있고, **쓰면 안 되는 표현까지 `avoid`에 적혀 있습니다.**

지금까지 이런 게 섞여 쓰였습니다.

- 셀 / 블록 / 육각형 / 그리드 → **셀**
- 스팟 / 장소 / 포인트 → **스팟**(사진 찍은 좌표)과 **장소**(검색되는 상호)는 다른 것
- 동선 / 경로 / 루트 → **동선**
- 외부 앱 → STOG는 **공유 담기**, STOG → 외부 앱은 **내보내기**

코드 변수명, 커밋 메시지, UI 문구 전부 해당합니다. 새 용어가 필요하면 glossary에 먼저 추가하고 쓰세요.

### 과하게 만들지 마세요

- **`cells` 테이블을 만들지 마세요.** 셀은 좌표로 계산됩니다. 저장하는 게 아닙니다
- **그룹 동기화에 WebSocket 쓰지 마세요.** 동시 편집을 안 하기로 했으니 조회와 갱신이면 충분합니다
- **추천 "모델"은 처음엔 스코어링 함수입니다.** 사용자 데이터가 0인데 학습을 시킬 수 없습니다

### 세 가지 방법론은 범위를 좁혀서

4주에 정석대로 다 하면 개발이 안 끝납니다.

- **DDD** — Bounded Context 나누기와 용어 사전까지만. Aggregate·Repository 같은 전술 패턴은 안 합니다
- **TDD** — 판정 로직에만. 방문/통과, 쿠폰 조건, 성향 점수, 좌표→셀 변환. 전부 순수 함수라 테스트가 쉽고 틀리면 치명적입니다. UI·통합 테스트는 안 합니다
- **SDD** — 여기에 힘을 싣습니다. yaml 스펙을 먼저 쓰고 그걸 근거로 구현합니다

### 컴포넌트는 두 개만 잘 만들면 됩니다

- **CellView** — 셀 상태가 6종이지만 컴포넌트는 하나입니다. `background`(빈/방문/불타는) + `badges[]`(꿀/무지개/아이콘, 최대 2개)
- **PlaceCard** — 바구니 카드, 링크 블록, 추천 장소, 행사, 피드가 전부 같은 구조입니다. variant로 처리합니다

## 데모는 이렇게 흘러갑니다

**1막 · 여행 전** — 인스타에서 본 카페를 공유 담기로 담기 → 검색으로 더 담기 → 카드 순서 조정 → AI가 일정 조정 제안 → 도보+버스 동선 확정

**2막 · 여행 중** — 여행 시작 → 셀이 채워짐 → 경기전 30분 체류, 방문 판정 → "어떠셨나요?" → 꿀 셀 쿠폰 → 매장 QR

**3막 · 여행 후** — 보관함 → 지도에 남은 동선 → 사진이 게시물로 정리 → 공개 전환 → 좋아요와 일정 복사

**1막은 반드시 공유 담기로 시작하고, 마지막은 반드시 여행 후로 끝냅니다.** 앞은 차별점이고 뒤는 우리 우선순위 1위입니다.
